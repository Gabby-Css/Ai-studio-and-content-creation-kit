# Prompt — curate a bounded, rights-aware asset collection

Use this prompt for one explicitly authorized curation pass. It is not a background harvesting policy, recurring task, minimum-download target, or permission to spend. Set a concrete creative need, source list, storage budget, time limit, and stop condition before starting.

## Distinguish references from reusable assets

- **Study references:** retain links and written technique notes. Download or capture material only when access terms and permissions allow it; a study purpose is not universal copying permission.
- **Production assets:** require documented rights for the intended output, modification, attribution, and any redistribution. A price of zero, a “royalty-free” label, or a site category alone is insufficient.
- **Unverified material:** record the uncertainty; do not mark it usable or include it in a deliverable.

Third-party reference footage, thumbnails, and reference plates are omitted from the kit. Add your own owned/licensed files, following `references/ADD-YOUR-OWN-LICENSED-MEDIA.md` and `LICENSES.md`.

## One bounded pass

1. Name the missing technique or asset needed for the current brief.
2. Consult candidate sources in `pipeline/ARSENAL-REFERENCES.md`. Availability and terms must be checked for the actual item.
3. Inspect a permitted preview. Record motion type, palette, framing, timing, and the transferable technique.
4. Before downloading, record source URL, creator, license/permission, attribution, permitted uses, access restrictions, and expected size. Ask before login, payment, or a material storage expansion.
5. Save only authorized material in a recipient-selected folder. Keep study references separate from cleared production assets.
6. Add an index record with path, source, review date, license evidence, rights scope, size, tags, and review status.
7. Write a candidate craft observation in `pipeline/playbooks/` and test it against a real edit.
8. Stop at the agreed limit. Report what was acquired, what remains unverified, and remaining gaps; do not pad the collection to reach a size quota.

## Useful source categories

| Need | Candidate source types |
|---|---|
| Unreal scenes and examples | Engine sample documentation, marketplace listings, artist breakdowns |
| Three.js and shaders | Official examples and repositories with explicit code licenses |
| Remotion components | Template sources with terms covering the intended use |
| Motion references | Authorized studio reels and published breakdowns, generally retained as links |
| Narration | Own recordings, consented voice references, licensed voice providers |
| Captions and fonts | Caption examples and fonts with verifiable embedding/distribution terms |
| Finishing | LUT, grain, and overlay sources with item-level license evidence |
| Audio | SFX/music catalogs; distinguish output use from asset-pack redistribution |
| HDRIs and materials | Asset catalogs with provenance and explicit rights |
| Stock inserts | Individually reviewed clips, releases, and license scope |
| Evaluation | Own content and rights-cleared comparisons; model scores remain experimental |

## Index and automation boundaries

The included catalog/fetcher is described in `assets/arsenal-README.md`. Inspect its sources and behavior before running it. A catalog entry or working downloader is not a rights clearance.

A custom curation importer, scheduler, or automatic downloader is not included in this prompt. Any future automation needs explicit scope, access controls, rate limits, budget, deduplication, and stop rules. Do not inherit the original author's schedules, personal folders, or background permissions.

Companion craft: `pipeline/MONTAGE-CRAFT.md`. Production map: `pipeline/STACK.md` and `pipeline/STUDIO.md`. Record improved quality only after measured comparison; a larger library is not evidence of better results.
